# Contributing

Thanks for helping make Project Architect useful beyond its original environment.

- **Bug or specific improvement:** open an Issue using the appropriate template.
- **Question, usage example, or broad idea:** use GitHub Discussions when enabled.
- **Ready change:** open a Pull Request with the behavior, scope, verification, and compatibility impact.

For code or template changes, work on a branch. Run `python3 -m unittest discover -s tests -v` and validate a generated project with the commands in [Getting started](docs/GETTING_STARTED.md). Keep each PR focused. Explain which exact code revision and evidence you tested. Do not describe a test as passed if you did not run it. A changed candidate needs fresh review.

Check for project names, local paths, credentials, personal data, and raw logs before submitting. Use fictional examples. Please do not include anyone else's private skill, chat, source code, or production payload. Maintainers may ask for a minimal redacted reproduction.

Issues and PRs are reviewed as time permits; opening one does not promise support or a release date. Be respectful and discuss the proposal, not the person.
