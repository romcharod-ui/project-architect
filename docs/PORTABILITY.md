# Portability

## Source of truth

GitHub releases are the source of installable skill and ChatGPT coordinator
versions. Projects should
record the foundation version in `.codex/project-foundation.json`.

Do not bootstrap from an unpinned moving branch when reproducibility matters.

## Codex profiles

Skills are local to the active Codex profile. Typical Windows and WSL/macOS
profiles do not automatically share installed skills. Install the same pinned
release separately in each environment that needs it.

Repository-native files generated by the skill travel with the project through
Git and continue to apply even when the global skill is not installed.

The ordinary chat does not automatically receive locally installed Codex
skills. It reads versioned `/CHAT_START.md` and the routed `chat/` protocol
through an authorized GitHub connection or user-provided attachments.

## Technology profiles

The core template is platform-neutral. A profile may add tooling only when its
environment and stack assumptions hold.

The Node.js + PostgreSQL profile avoids embedding operating-system-specific
PostgreSQL package lists from any particular project. A founded project chooses a managed
installation, pinned container, or checksum-pinned extracted cache appropriate
to its own OS and CI.

## Upgrades

Do not blindly rerun a newer bootstrap over an existing project. Compare the
foundation release, project decisions, and generated files; apply an upgrade as
a reviewed governance stage that preserves local accepted rules.
